This is a plan to reachitecture the app into a cleaner architecture that needs less manual work.

All the data is already stored in a google sheet file. So instead of manually downloading it, preprocessing it and then uploading it to the repo we can use app script to preprocess the data and then copy the result to a public google sheet from where we can fetch it directly into the app on the frontend. This will also allow us to update the data without having to update the app itself.

# Backend (Google sheet app script)

The source sheet will be structured into multiple sheets as follows:

1. `Zbirni seznam` - the main sheet that will contain all the data about players and their scores. This will be the source of truth for all the data. This is where all the data/data*2026*\*.csv files came from today.
2. `Rezultati` - a sheet that will contain what is today written by `data/preprocess_data.py` as well as transformations done in the svelte app. This is essentially "godmode" as defined in the app today. It includes all the scores, all the results and final grades.
3. `Vzdevki` - a sheet that will contain the nicknames of players. This will be append only and will contain animal aliases for players. Each run of the script will append nicknames for the players that don't have a nickname yet.
4. `Živali`, `Pridevniki` - these sheets will contain the list of animals and adjectives that will be used to generate nicknames for players. This will just be copies of data/animals.txt and data/adj.txt
5. `Izjeme` - a sheet that will contain a list of overrides for which group a player belongs to. This will be a copy of data/izjeme_2026_05_08.csv
6. `Javni` - a sheet that will contain the public data that will be fetched by the frontend. We will call this the "database". The structure of this is defined the next session.

Any other sheet should be ignored.

# Database (public sheet)

The public sheet will contain the following columns:

- `Vzdevek` - the animal nickname of the player.
- `Predlog Skupine` - the suggested group of the player based on their scores.
- `Spodnji odboj sede`, `Zgornji - spodnji odboj`, `Spodnji odboj z dotikom tal`, `Telesna višina`- these will be direct copies from the source `Zbirni seznam` sheet.
- `Godmode` - this will be an encrypted json of all the data that is only exposed to the users with godmode access on the frontend. It should be encrypted with the same key as today is gibit_z_imeni2.json.enc. The encryption will be done in the app script and the key will be stored in the script properties. The frontend will fetch this data and decrypt it using the same key. The json should contain the real name of the player, their computed scores based on exercises, their coach scores for all categories and their final numeric grade.

# Frontend (Svelte app)

The frontend will fetch the public sheet and display the data in a table, same as today. The current page at the root and on /2026 should be removed and replaced with a single page that will display the data from the public sheet.

The code should just fetch the data and display the table. Keep the godmode detection functionality as it is today. If there exists godmode query parameter in the url, the app should fetch the `Godmode` column and decrypt it using the key stored in the app. The decrypted data should be used to display the real names of players and their scores.
